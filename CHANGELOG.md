# Changelog

## Unreleased

## 0.4.1

Hermes Gadget 0.4.1 fixes `hermes gadget update --latest`, which could install an older release over a device running newer firmware, such as a build from `main`. The firmware is unchanged from 0.4.0 apart from its version number.

### Hermes plugin

- `hermes gadget update <device> --latest` no longer installs an older release over a device that runs newer firmware. It compares the leading `MAJOR.MINOR.PATCH` numbers, so 0.10.0 is newer than 0.9.0 and a source build such as `0.4.0-12-gabc1234` counts as at least 0.4.0. A device on the release's version or a newer one gets a one-line message and nothing installed; a device whose version is missing or unreadable is refused with a message. `--force` installs the release in every case. Reported by @mforce.

### Upgrade

Update the plugin with the commit-pinned command in the release notes, in every Hermes profile that has a copy. Devices on 0.4.0 don't need new firmware; `--latest` will offer 0.4.1, and taking it changes nothing but the reported version.

## 0.4.0

Hermes Gadget 0.4.0 gives each Hermes profile its own face on the device, adds countdown timers that Hermes sets through device actions, face-down sleep on boards with a motion sensor, and a resting clock kept by network time and the board's RTC. It adds two experimental boards, the ESP32-2432S028 "Cheap Yellow Display" (the first classic ESP32 profile, drawn in bands without PSRAM) and the Waveshare ESP32-P4-WIFI6-Touch-LCD-3.4C. Profile switching no longer writes into other Hermes profiles and keeps the default profile's verdict even under a static route, and a switching device's dashboard lists the offered profiles' sessions, in order. Details by area follow.

### Hardware and setup

- Experimental board support for the ESP32-2432S028 "Cheap Yellow Display" (`esp32-2432s028-cyd`), the revision with two USB ports: a classic ESP32-WROOM-32 with 4 MB flash and no PSRAM, a 320×240 ST7789 on SPI2 and BOOT as the only key. The original micro-USB-only CYD has an ILI9341 panel and is not supported by this profile. It is the first classic-ESP32 profile, so the RGB, i80-parallel, MIPI-DSI and audio-codec drivers are compiled out and the panel uses the existing SPI `SpiDisplay` path and ESP-IDF's built-in ST7789 driver. No PSRAM means the full 150 KB framebuffer does not fit in internal RAM, so the port holds a 120-row band (75 KB) instead, reserved in an early constructor before the heap fragments, and flushes through a four-row bounce buffer; the UI renders each changed band once per window, so the screen is drawn in full without a whole-panel buffer. The board's XPT2046 touchscreen and microSD are not brought up. The SC8002B amplifier behind the speaker header is fed by the chip's own DAC on GPIO26 and plays three boot beeps, so the amplifier and a speaker can be checked before replies are routed there; those still come out as text. The 4-pin header also takes a PDM MEMS microphone (clock on GPIO22, data on GPIO27, SELECT tied to ground), read through the classic ESP32's PDM-to-PCM converter on I2S0 — the same path the P4 profile uses; the stock board has no microphone fitted, and an I²S microphone (three signal lines) cannot be used on those pins. A display that holds only a band of rows doesn't offer `display.image` in its hello, so Hermes shows its unsupported-image notice instead of sending an image the board would drop. Experimental: the firmware builds, but it has not been run on a board and the physical checklist is not completed. The pin map follows the community ESP32-Cheap-Yellow-Display reference. Contributed by Tony Tran (@thanhtantran).
- Experimental support for the Waveshare ESP32-P4-WIFI6-Touch-LCD-3.4C (SKU 31523): round 800×800 MIPI-DSI JD9365 panel, GT911 touch, ES8311 speaker with ES7210 microphones, and Wi-Fi 6 through the ESP32-C6 companion over 4-bit SDIO. The DSI driver now selects its panel controller (EK79007 or JD9365) from the board config instead of hardcoding the CrowPanel's EK79007. The profile builds with `idf.py`, since PlatformIO has no ESP32-P4 target (CI builds it; releases don't include it yet), and needs `CONFIG_ESP_CONSOLE_USB_SERIAL_JTAG` for the console, plus an esp_hosted slave image flashed to the C6 over its own UART header. Experimental: owner-confirmed display, C6-hosted Wi-Fi, pairing, reconnect after restart, factory reset and a one-hour run; touch, microphone, speaker and the full checklist are not verified. Contributed by Richard Ahlquist (@rahlquist).

### Firmware

- Each Hermes profile can have its own face. The plugin sends the face of the profile that answers a device: the profile's `gadget-face.bin`, made with `hermes-gadget face --out gadget-face.bin`, or else its Hermes avatar (`assets/avatar.*`) made into a still face when Pillow is installed. Without either, the device shows the mascot. A profile a device switched to shows its face once the default profile trusts the device; a profile a gadget route sends it to shows its face once that profile accepts the device. The device keeps the face in memory through reconnects, and shows the mascot after a profile switch until the new face arrives. `platforms.gadget.extra.profile_faces: false` turns faces off. Firmware without the feature keeps the mascot; the protocol adds `caps.faces`, `hello.face` and a `face` message, and stays at version 1. Contributed by @mforce.
- Face-down sleep, off by default, on boards with a motion sensor and a backlit display (first the Waveshare ESP32-S3-Touch-AMOLED-1.75): turn it on with the new **Face-down sleep** settings item or `set face_down_sleep on`. After about a second face down the screen goes dark, listening is cancelled and Hermes goes quiet: a reply being spoken stops and speech that arrives face down is dropped, while the turn carries on. The reply's text shows from the top when the gadget is turned back over. A ringing timer alarm goes quiet and stays quiet after the turn-over; a timer that ends face down still rings, with the screen dark. Adds a QMI8658 accelerometer driver (`firmware/drivers/qmi8658.cpp`). The simulator's `sim-466x466-round` board has the sensor (Developer tools **Face down**, script command `facedown on|off`); rebuild its native library for ABI 7. Contributed by @momoshamiko.
- Resting clock, off by default, on every board with a display: after the `clock` setting's seconds of rest on an online, paired Ready screen, the screen shows the time and the date, with the profile's face or the mascot, at 70 percent of the brightness setting, shifting a little each minute; a quick tap brings Ready back, and anything on screen keeps the clock away — speech or a reply, a card or a picture shown until dismissed, a question, a notice, a running timer, the alarm, the low-battery warning or the settings menu. Set it with the **Clock face** item (Off, 30 s, 1, 2 or 5 min) or `set clock` (0 or 5..3600 seconds), with `set time_format 12h` for 12-hour time and, on the ESP32 port, `set timezone` (POSIX TZ string, default `UTC0`). Network time (SNTP, `pool.ntp.org`) is fetched only while the clock is on; boards with a PCF85063 (AMOLED-1.75, 2.06, 2.16) keep UTC across resets and are set from each sync. A `screen.brightness` action no longer lights a dimmed or timed-out screen: the new level applies when it wakes. The simulator's `time` script command pins the clock's time; rebuild its native library for ABI 8. Contributed by @momoshamiko.
- Audio written right after a speaker stream starts is no longer thrown away on boards whose speaker task empties its queue after an abort: I2S speakers, and codec speakers without `codec.speaker_pa`. `begin()` aborts the stream before it, and the task emptied the queue on its next pass, so audio queued in between, such as a short tone written at once, could go with it. When `begin()` replaces a stream it now waits for that reset, at most 6 ticks (about 60 ms), as the P4 speaker also waits in `begin()`, so `write()` stays non-blocking, and an idle speaker starts at once. The task drops what it received while a reset was pending, and a codec cuts a stream's silent tail short when the next stream waits. A codec stream that closes with nothing played also no longer leaves `busy()` true until the next stream, which kept the screen from sleeping. Contributed by @momoshamiko.
- Timers: Hermes can start, check and cancel one countdown timer with the device actions `timer.start`, `timer.status` and `timer.cancel`, on any board with a display or a speaker. The time left shows on every screen: an arc around the edge of round screens, a line under the top bar of rectangular ones, and "Timer 6:18" on the Ready screen. At zero the screen shows TIMER DONE with the timer's name, and a board with a speaker beeps for a minute. A press, a tap or swipe, or `timer.cancel` stops the alarm. Contributed by @momoshamiko.

### Hermes plugin

- Profile switching no longer writes into other Hermes profiles. The plugin used to approve a switching device in each profile's pairing store itself; now each profile approves it through its own pairing flow the first time the device talks to it, and the device shows the command to run (`hermes -p <profile> pairing approve gadget <code>`) instead of waiting for a reply. The default profile's verdict comes from the adapter's own sender check. A device that has switched but that a static route now sends elsewhere is refused, so another profile's approval never stands in for the default one (found by @mforce). Asked for in the Hermes plugin catalog review ([NousResearch/hermes-agent#142936](https://github.com/NousResearch/hermes-agent/pull/142936)).
- Validate device-selected profiles during Hermes native session admission and durable replay, retaining Default-owner trust, offered-profile policy and owner binding. Requires the matching Hermes `validate_native_profile_route` hook; without it, a secondary profile can be selected but ordinary messages fail with `profile_mismatch`. Contributed by @bricelb.
- With profile switching on, a gadget that can switch profiles also lists on its dashboard the sessions of the other profiles it may switch to, where the gadget plugin is enabled, so a device switched to another profile sees its sessions there. Hermes loads a copy of the plugin per profile, and each copy records only its own profile's sessions; the default profile's adapter now also reads those of the offered profiles. With switching off, and on devices that cannot switch or that a profile route sends somewhere, the dashboard is as before. [User guide](docs/using-gadget.md#watch-hermes-sessions-on-the-dashboard). Contributed by @mforce.
- A switching gadget's dashboard no longer shows a profile that has just left the offer, or misses one just added, when two updates overlap, and a gadget that cannot switch no longer stops the other profiles' changes reaching it. Reading the profile list never makes a connecting gadget wait for a slow one. A dashboard held while the screen is dark is dropped if a newer one goes out first, and is never sent to a device that is unpaired or reconnects without dashboard support. Contributed by @mforce.

### Upgrade and verification

Use the [browser installer](https://adolanium.github.io/hermes-gadget-sdk/installer.html) for USB installation. Existing devices can use `hermes gadget update <device> --latest`. Install the matching plugin using the commit-pinned command in the release notes, and update the copy in every cloned Hermes profile too (see [One profile per gadget](docs/hermes-integration.md#one-profile-per-gadget)). Old firmware keeps working with this plugin, and this firmware with the 0.3.0 plugin. Faces need both updated; timers, face-down sleep and the resting clock need the new firmware. A device that has switched profiles and that a static `gateway.profile_routes` entry now sends elsewhere is refused; remove the route and let it switch instead. Device-selected secondary profiles on Hermes versions with session-authority admission also need the Hermes `validate_native_profile_route` hook. The simulator's native library is at ABI 8; rebuild it with `hermes-gadget build-sim`.

Hardware ports remain experimental until a complete physical report is recorded for the exact revision; see [hardware capabilities and verification](docs/hardware-validation.md). Software tests and successful builds do not establish physical hardware verification.

## 0.3.0

Hermes Gadget 0.3.0 adds twelve board profiles, among them the first ESP32-P4 board (the Elecrow CrowPanel Advanced 10.1"), Opus speaker audio, device text in Spanish with a Latin-1 font that can follow Hermes's own language, switching Hermes profiles from the gadget, and a session dashboard. It also brings many reliability fixes for audio, Wi-Fi, power and the plugin. Details by area follow.

### Hardware and setup

- The Waveshare Touch-LCD-1.54 (SKUs 33868/33869) now uses its CST816 touchscreen, and the PWR key of every LCD-1.54 works: a short press turns the screen off and on, and holding it for 2.5 seconds powers the board off on battery. Battery latches can now read a power key on a GPIO (`latch_power.key`, active low). On the non-touch SKUs the touchscreen is reported absent. Contributed by Luiz Gustavo Saraiva (@luizgustavosaraiva).
- The AMOLED-1.8's PWR key works as CANCEL: a press cancels and holding it for two seconds starts a new conversation. Its level reaches TCA9554 pin P4, as on the AMOLED-1.75, and was read there on a V2 board: `diag` reports `key: true`, and a press cancelled a recording. Before, the board had no CANCEL button, only the downward swipe. Contributed by Alberto Espinosa (@AlbertoEJ).
- Board support for the Waveshare ESP32-S3-Knob-Touch-LCD-1.8: round 360×360 SH8601 QSPI LCD (Espressif's `esp_lcd_sh8601`), CST816S touch, one PDM microphone, a rotary encoder that scrolls, ESP32-S3R8 with 16 MB flash and 8 MB PSRAM. Hold the screen or BOOT to talk. The port doesn't drive the board's headphone DAC, so replies are shown as text and not played. The panel's initialization table comes from Waveshare's ESP-IDF demo. Adds a `sim-360x360-knob` simulator profile. Experimental: a contributor test showed the display, hold-to-talk touch and microphone capture through a full voice turn; the full checklist is not completed. Contributed by @Delphus123.
- With `latch_power.usb_external_power`, the latch power driver reports external power while the charging signal is on or a USB host is connected to the S3's own USB port. Boards with a battery latch and no USB-status input could not tell battery from USB, so Wi-Fi modem sleep never applied on battery. The Spotpear muma now reports its battery voltage (divider by two on GPIO 1) and charging signal (GPIO 41), and both the muma and the Waveshare LCD-1.54 report external power. Contributed by Luiz Gustavo Saraiva (@luizgustavosaraiva).
- Board support for Espressif's ESP-VoCat, v1.2 only: round 360×360 ST77916 QSPI panel, CST816S touch, ES7210 microphones, ES8311 speaker output through an NS4150B amplifier, 16 MB flash and 16 MB PSRAM. BOOT talks as well as the screen. The panel takes Espressif's own start-up table from the ESP-VoCat BSP, so ST77916 boards can now choose their table (`lcd.st77916_panel`) instead of having it picked by the Waveshare panel ID, and boards can switch GPIO-driven supplies on at boot (`power_rails`), which the VoCat needs for its LCD/SD rail and codec supply. The BMI270 IMU, BQ27220 fuel gauge, head touch pads and LED are not used yet. Experimental: a contributor smoke test on USB power covered boot, display, both codecs, touch, Wi-Fi, pairing and a hold-to-talk voice turn; the full checklist is not completed. Contributed by @dreamhunter02.
- Board support for the Waveshare ESP32-S3-Touch-AMOLED-2.16 (SKU 33969): square 480×480 CO5300 AMOLED, CST9220 touch (read with the CST9217 report), ES7210 microphones, ES8311 speaker output, AXP2101 PMIC, 16 MB flash and 8 MB PSRAM. BOOT talks as well as the screen, and PWR's short press puts the screen to sleep. Touch boards can now swap x and y (`touch.swap_xy`, CST9217 report only), which this board needs to match its rotated picture. Adds a `sim-480x480` simulator profile. Experimental: a boot smoke check on USB power passed; touch coordinates, audio, battery and the rest of the checklist are not verified. Contributed by Joerg Peetz (@JPeetz).
- Board support for the Spotpear ESP32-S3-1.28-BOX (SKU `sp-esp32-s3-1.28-box`), the round robot: 240×240 round GC9A01 SPI panel, one ES8311 for the speaker and the microphone, CST816D touch on its own I2C bus, BOOT key, a GPIO3 battery latch with power-off, battery voltage and charging, ESP32-S3R8 with 16 MB flash. SPI boards can now use a GC9A01 panel (`LcdController::Gc9a01`, Espressif's `esp_lcd_gc9a01`), with per-panel register changes after the driver's default bring-up (`lcd.gc9a01_panel`), and battery latches can read a charging signal that is high while charging (`latch_power.charging_active_high`). Adds a `sim-240x240-round` simulator profile. Experimental: built, not yet run on a board.
- Board support for the Spotpear ESP32-S3-1.54 "muma" (SKU `sp-esp32-s3-1.54-muma`): 240×240 ST7789 SPI panel, one ES8311 for the speaker and the microphone, CST816D touch, BOOT key and a GPIO3 battery latch, ESP32-S3R8 with 16 MB flash. Its touch controller has an I2C bus of its own, so boards can now give the touchscreen separate pins (`touch.bus`), opened on the second I2C controller. Battery level and charging are not reported yet. Experimental: two touch units passed a smoke test on USB power (display, touch, Wi-Fi setup from a phone, pairing, voice turns, volume and brightness set by the agent). Contributed by Luiz Gustavo Saraiva (@luizgustavosaraiva).
- Board support for the Waveshare ESP32-S3-Touch-AMOLED-2.06 watch: 410×502 CO5300 AMOLED with rounded corners, FT3168 touch, ES7210 microphones, ES8311 onboard speaker, AXP2101 PMIC, 32 MB flash and 8 MB PSRAM. BOOT talks as well as the screen, and PWR's short press (read from the AXP2101) puts the screen to sleep. Its microphones are quiet (speech about 170 RMS at the usual 24 dB), so the profile raises the gain to 30 dB, and boards can now set tap mode's speech floor (`codec.vad_min_rms`, 200 here instead of 500). Its FT3168 dozes after a few idle seconds: it then refuses most reads, and reports the touch that wakes it with a single short INT pulse. Polled every 20 ms, an idle watch logged an I2C error on most polls and lost the first tap after a pause. An FT5x06-family controller whose board wires INT (`touch.int_gpio`) is now read on the pin's falling edge, from an interrupt, and not read at all without a finger or an edge. Adds a `sim-410x486` simulator profile. Experimental. Contributed by Geo (@Geofresh).
- Board support for the Elecrow CrowPanel 5.0-inch HMI (DIS07050H): 800×480 ILI6122/ILI5960 RGB panel, GT911 capacitive touch, ESP32-S3-WROOM-1-N4R8 with 8 MB PSRAM. The shared RGB display driver now also drives a panel with no command bring-up, expander or enable line (the ILI6122) alongside the CrowPanel 2.1-inch's ST7701-over-PCF8574 path, and takes its scanout timings and red/blue order from the board config. The touch driver reads its IRQ pin from the board config instead of a fixed GPIO. Experimental: a boot smoke check passed, but rendering, colours, brightness and touch coordinates are not yet verified. Contributed by Richard Ahlquist (@rahlquist).
- Experimental support for the Elecrow CrowPanel Advanced 10.1-inch ESP32-P4 V1.1: 1024×600 MIPI-DSI EK79007 display, GT911 touch, PDM microphone through the existing Gadget I2S microphone port, P4-specific stereo I2S1 speaker adapter, STC8 battery/charger values mapped only to the existing Gadget PowerStatus fields, and ESP32-C6 Wi-Fi over SDIO. Uses ESP-IDF 6.1.0 and pinned Espressif component versions (`esp_lcd_st7701` 2.0.2 on the P4 only; other boards keep 1.1.0); the profile has a dedicated P4 build job. The current upstream-based port has not been physically validated; earlier hardware observations are recorded separately and are not attributed to this build. Contributed by Richard Ahlquist (@rahlquist).
- The AMOLED-1.75C (SKU 33691) has a physical report in the hardware verification guide. It covers the whole checklist on a working branch rather than a build of `main`, and found the refused OTA updates and the freeze after a Wi-Fi loss that are fixed under Firmware. The port stays experimental. Contributed by Antonio Lourenco (@tozes).
- Show a QR code on the Wi-Fi setup screen so a phone camera can join the gadget's temporary network without typing. The code encodes the network name and password with the standard `WIFI:` scheme. The instructions stay printed beside it, since the phone still opens the setup address and some phones cannot scan. Screens without room for a scannable code beside the instructions keep the text-only screen.
- Boards whose AXP2101 fuel gauge reports no valid estimate, such as the AMOLED-1.75C where it is never initialized and reads 0 on a full cell, now estimate the battery percentage from the cell voltage, so the low-battery reminder no longer sticks on a full battery. Contributed by MacroAnarchy.
- Releases include the CrowPanel Advanced P4 (`crowpanel-p4-101`): its image, OTA app, manifest entry, checksums and provenance attestation are published with the other boards, and the browser installer lists it. PlatformIO can't build the ESP32-P4, so the release builds it with `idf.py` in the same pinned ESP-IDF 6.1.0 container as CI, and `tools/stage_idf_build.py` hands that build to the packager. The packager now places the ESP32-P4 bootloader at 0x2000, where its ROM looks for it; an image with the bootloader at 0 would not boot. CI's P4 job packages the board too and keeps the image as the `firmware-crowpanel-p4-101` artifact. The installer no longer warns about PSRAM on the ESP32-P4, whose in-package PSRAM esptool doesn't report.

### Firmware

- The `language` setting takes `auto`: the device shows its own text in the language Hermes names in `welcome`, matched by id and then by primary subtag (`es-mx` as `es`), and in English when Hermes names none or one the firmware lacks. English stays the default. The settings item steps through the languages and then **Automatic, as Hermes**, `screen.language` accepts `auto`, and `status` reports `language` and `language_auto`. Contributed by Alberto Espinosa (@AlbertoEJ).
- The font draws Latin-1 (U+00A0 to U+00FF): accented letters, ñ, ç, ¿, ¡, °, « » and the rest, in the same 5x7 cell. An accented capital is its letter on five rows under the accent; a small letter sits on four rows with a blank row under the accent, so ó and Ó differ. Text is now read as UTF-8 everywhere it is drawn, measured, wrapped or cut, so a letter is one column however many bytes it takes; a code point outside the font draws as `?`. Translations show as written ("Información", "¿Lo oíste?"), and the device reports `charset: "latin1"` in `hello`, so the plugin stops folding accents for it. Tests check every Latin-1 glyph is its own, UTF-8 decoding survives malformed input, and wrapping and cuts never split a letter. Contributed by Alberto Espinosa (@AlbertoEJ).
- Spoken replies can travel as Opus: devices that decode it list `"opus"` in `caps.speaker.formats`, and the plugin then sends one Opus packet per 40 ms frame at 24 kbps (`opus_bitrate`, 0 for PCM16), about a tenth of PCM16 at 16 kHz. ESP32 boards with a speaker decode it with Xiph's libopus (the `78/esp-opus` component); the plugin encodes through the host's libopus and keeps PCM16 without it. Older firmware and servers keep PCM16. On one home Wi-Fi link, a board that logged 60 to 113 speaker underruns per reply with PCM16 logged none with Opus. The main task's stack grows from 8 to 20 KB for libopus's decoder scratch. Contributed by Luiz Gustavo Saraiva (@luizgustavosaraiva).
- The opt-in voltage estimate (`set battery_estimate liion`) follows a typical single-cell Li-ion resting-voltage curve instead of a straight 3.3–4.2 V line, which read up to about 20 points high in the middle of the discharge (3770 mV is now 30%, not 52%; 3840 mV is 50%, not 60%). A voltage reads high on a charger, so while the board reports charging or external power the title bar shows the battery icon with a charging bolt and no number, whatever the indicator style, and the Power page marks the value as high on a charger. The charging icon now draws a bolt over a dim green fill, so it reads at any level. Gauge percentages (AXP2101) are unchanged. Contributed by Luiz Gustavo Saraiva (@luizgustavosaraiva).
- The Waveshare LCD-1.54 and the Spotpear muma save battery like the AMOLED-1.75C: the CPU drops to 80 MHz when idle, and while the screen is dark on battery the chip takes light sleep between Wi-Fi beacons. Light sleep now keeps a battery latch's enable pin, an SPI panel's control lines and a separate touch bus at their level; before, a latch-powered board would cut its own supply on its first light sleep. Contributed by Luiz Gustavo Saraiva (@luizgustavosaraiva).
- Holding the title bar opens settings on the AMOLED-1.8 again. Its touch controller reports glass rows, and the UI starts 8 rows down (`touch.offset_y`), so touches on the top rows of the glass came out at negative rows (`y = -7` on a V2 board) and missed the title strip: holding the title started a recording instead. Rows above the UI now count as its first row. The AMOLED-2.06 uses the same offset and gets the same fix; it was not checked on hardware. Contributed by Alberto Espinosa (@AlbertoEJ).
- The device's own text can be shown in another language: Spanish for now, and more by adding a translation file. The strings moved into one catalogue (`hg/i18n.hpp`) with a table per language that falls back to English for anything it leaves out, and placeholders so a translation can order the words its own way. A `language` setting (`en` by default, or `es`) is chosen from a new **Language** item in device settings, with `set language` on the console, or by asking Hermes, through a new `screen.language` device action. Translations are written with their accents and shown without them until the font draws them. Tests check each translation is complete, keeps the English placeholders, and fits on one line wherever the English does on every supported screen size. Replies from Hermes are not affected. Contributed by Alberto Espinosa (@AlbertoEJ).
- Frame timing for renderer work: the console's `perf` command reports drawing, flush and whole-update times (min, average, p50, p95, max), bands sent per update, updates over a frame budget, and the time from a button or touch to the update that shows it. `perf bench` draws three fixed workloads (scrolling a long reply, the talking mascot, full repaints) so a change can be measured before and after; `examples/scripts/perf.txt` runs it in the simulator. Off by default (`perf on`, or `CONFIG_HG_FRAME_STATS` from boot); while off, the renderer never reads the clock. The HAL's `System` gains `now_us()`. See the development guide.
- Rejoining Wi-Fi skips the channel scan. After each good join the device records the access point's BSSID and channel (NVS key `wifi_fast`). At boot and after the link drops, the first attempt aims straight at it. If that attempt fails, the device joins normally at once, and the failure doesn't count against the network or lengthen the battery backoff. DHCP asks for the last address first (`CONFIG_LWIP_DHCP_RESTORE_LAST_IP`), and `CONFIG_HG_WIFI_REUSE_IP` (off by default) reuses the last lease as a static address for routers that reserve it. Reconnect times were not measured on hardware. Prompted by @dcentgeo's ESP32-S3 watch build.
- The device tells Hermes when its screen goes dark and lights up (`display_sleeping` in `hello` and in `state`), so the plugin can hold back screen updates; see the Hermes plugin entry.
- A connection that the server, a reverse proxy or a tunnel drops no longer leaves the device wedged until a reset. Firmware 0.2.0 waited on the WebSocket client from the app task, so a dropped connection could stop that task for good: the event queue filled (`event queue full; dropping event 6`), console commands were not applied, and the device never reconnected. On `main`, sends and closes already ran on their own task (the Wi-Fi-loss fix below). The last wait with no limit, handing a closed client to that task, now gives up after 1 s. If the send task spends more than a minute on one message or close, the device logs `the WebSocket send task is stuck; restarting` and restarts. Reported by @Taxgab.
- `wss://` servers behind Cloudflare, including quick tunnels (`*.trycloudflare.com`), pass certificate validation. Cloudflare sends GTS Root R4 cross-signed by GlobalSign Root CA, and the certificate bundle looked up only the issuer of the last certificate sent: GlobalSign Root CA is no longer in ESP-IDF's bundle, so the handshake failed with `No matching trusted root certificate found` although GTS Root R4 is bundled. Every board now enables ESP-IDF's cross-signed verification (`CONFIG_MBEDTLS_CERTIFICATE_BUNDLE_CROSS_SIGNED_VERIFY`), which trusts a chain at the first certificate a bundled root issued, for about 700 bytes of heap. The remote access guide explains how to check a server's chain. Reported by @Taxgab.
- Add an explicitly enabled, display-only single-cell Li-ion voltage estimate (`set battery_estimate liion`) for voltage-only power drivers, including LCD-1.54. Confirm a compatible fitted battery before enabling it; charging affects accuracy. Existing native percentages, raw telemetry, alarms, and default-off indicator settings are unchanged. The simulator now accepts full power readings through Python, scripted `power` JSON, and compact desktop controls; rebuild its native library for ABI 6. Contributed by Pablo Musaber (@PabloMusaber).
- AMOLED boards whose screen window is shorter than the glass (the 1.8 and the 2.06) blank the rows above and below it at start-up. Nothing else writes them, and the panel's memory starts out as noise: on the 2.06 it showed as green strips along the top and bottom edges. Seen and fixed on the 2.06; the 1.8 uses the same layout and was not checked on hardware. If clearing fails or times out, the gadget runs without the display so drawing cannot overwrite a pending DMA transfer. Contributed by Geo (@Geofresh).
- When a spoken reply finishes, the serial log reports how often the speaker ran out of audio mid-reply and for how long (`playback ended: N underruns, X ms in total, longest Y ms`), on every board with a speaker. Choppy replies on a weak link can now be measured instead of described. Contributed by Antonio Lourenco (@tozes).
- A recording no longer gets stuck on "Sending..." on a slow uplink. Microphone audio could fill the WebSocket send queue, so the message that ends the recording was refused and Hermes waited for the rest; the device showed "Thinking" for three minutes. The last slots of the queue are now kept for control messages, so audio is what gets dropped, and the serial log says how many frames of the recording weren't sent. If the end still can't be sent, the device shows "Couldn't send the recording" at once. Contributed by Antonio Lourenco (@tozes).
- The AMOLED-1.75C light-sleeps while dozing: on battery, with the screen off, idle and connected (or waiting between Wi-Fi attempts). The speaker codec and its I2S channel close while dozing, the speaker task waits instead of polling, and touch is checked every 50 ms. On USB it never light-sleeps, so the serial console, flashing and JTAG keep working. Waking the screen or plugging in retries Wi-Fi at once. Contributed by Antonio Lourenco (@tozes).
- The device keeps up to five Wi-Fi networks and joins whichever is in range. When the link drops it retries the same network once, then scans and picks the network that last worked if it is there, else the strongest saved one. A network that keeps failing is passed over while another is in range. The console's `wifi list`, `wifi add`, `wifi join` and `wifi forget` manage the list, and `wifi add` saves a network without joining it. `set wifi_ssid`, the web installer and phone setup now save their network first and keep the others. The first network is also kept under the old keys, so older firmware still finds it. Contributed by Antonio Lourenco (@tozes).
- An experimental Bluetooth LE link for a phone companion app. A paired phone sends the same commands as the USB console and gets the same replies, so an app can set up Wi-Fi, change settings and read the device's status. Pairing opens for two minutes from a new **Phone app** item in device settings or the `phone pair` command, and the phone types the six-digit code the screen shows. The link is off on every board: a board turns it on with a `BoardConfig` flag and NimBLE in its `sdkconfig.defaults` once it passes the Bluetooth checks in the hardware verification guide, so released images don't grow until then. Contributed by Antonio Lourenco (@tozes).
- Wi-Fi modem sleep is on only while the board runs on its battery and no turn is under way. Plugged in, on a board that cannot tell, or during a turn (from pressing TALK, through the wait while Hermes works, until the reply has finished playing), the radio stays awake, so reply audio no longer arrives in bursts that overflow the speaker buffer and crackle. Reported and diagnosed by @burndown; keeping the radio awake through a turn on battery contributed by Antonio Lourenco (@tozes).
- The I2S microphone driver (breadboard and custom-pin boards) keeps the samples of a read that times out part way. On ESP-IDF 6.0.1 nearly every read returned `ESP_ERR_TIMEOUT` with one DMA buffer filled, the driver dropped it, and a held TALK sent 0 bytes of audio, so Hermes never replied. Contributed by @burndown.
- A dark screen stays dark while Wi-Fi or the connection to Hermes drops and reconnects; it used to light up and, without a screen timeout, stay on until someone turned it off. Contributed by Antonio Lourenco (@tozes).
- The AMOLED-1.75C shows its battery percentage from a discharge curve measured on its 500 mAh cell, smoothed over a minute and never rising on battery, instead of the AXP2101 gauge, which read up to 14 points low on this cell, or the linear voltage estimate used when the gauge is invalid, which was off by up to 13 points. While charging it follows a charge curve measured on the same cell, never falling, and shows 100 once charging is done; `diag` reports the PMIC's charge current limit. Builds on the voltage fallback for invalid gauge readings. Contributed by Antonio Lourenco (@tozes).
- Boards with a separate ES7210 microphone ADC (the AMOLED-1.75 and 1.75C, the 1.85C V2 and the LCD-1.54) power it down between recordings instead of running and reading it continuously, which saves battery. Recording starts by draining the audio the I2S channel kept while the ADC was off and dropping 20 ms while it settles. Boards whose microphone shares the speaker's codec keep reading continuously. Contributed by Antonio Lourenco (@tozes).
- Boards that report a battery percentage show it at the top of the screen: a battery icon and the percentage in the title bar, or centred at the top edge of round displays, green while charging and red at 10 percent or less without USB. Selecting **Battery and power** in device settings cycles it through icon only, percentage only, both and off, when the board has a percentage to show; the console takes `set battery_display icon|percentage|both|off`. It is off by default and the choice survives restarts. Contributed by Antonio Lourenco (@tozes).
- On battery, Wi-Fi retries back off from 3 s to 30 s, like the Hermes reconnect, instead of trying every 3 s, so a long stretch without coverage costs little. Plugged in, they stay at every 3 s. Contributed by Antonio Lourenco (@tozes).
- AMOLED boards (the 1.75, 1.75C and 1.8) draw the background true black instead of near black, so those pixels stay off and draw no power. Backlit LCDs keep the near-black background. Display drivers opt in with `DisplayInfo::emissive`. Contributed by Antonio Lourenco (@tozes).
- Battery life on the AMOLED-1.75C: the speaker amplifier is powered only while sound plays, and the CPU scales down to 80 MHz when idle instead of running at 240 MHz. AMOLED panels also switch their output off during screen sleep, not only their brightness. Contributed by Antonio Lourenco (@tozes).
- The AMOLED-1.75C's PWR key puts the screen to sleep and wakes it with a short press. Only the AXP2101 sees this key, so the firmware enables the PMIC's short-press interrupt and polls it every 100 ms; holding PWR keeps the PMIC's own power behavior. Contributed by Antonio Lourenco (@tozes).
- The `diag` report's I2C scan no longer gives up at the first probe that times out. On the AMOLED-1.75C it reported `bus stuck` after `0x18` while the AXP2101 at `0x34` was answering battery reads. A probe waited 10 ms, a single tick at the firmware's 100 Hz tick rate, which can run out before the transfer ends; a probe also times out while touch, codec or battery reads hold the bus. Each address now gets up to three 50 ms tries. An address that never answers is listed as `timeout at 0x19` and the scan goes on; only four in a row end it, as `bus stuck at` the first of them. `hermes-gadget diag` now separates the entries with commas. The scan is host-tested.
- Boards that play through an ES8311 or AW88298 codec run their audio at 24 kHz instead of 16 kHz and buffer 192 KB of speaker audio in PSRAM instead of 48 KB, so they absorb a longer Wi-Fi burst before dropping audio. They play silence into the I2S DMA buffer before muting, so the end of a reply is no longer cut off. Contributed by 0xdfi.
- A weak or lost Wi-Fi link no longer freezes the device until a hard reset. Closing the WebSocket used esp_websocket_client_close(), which sends its close frame with no time limit and blocked the app task, and with it the screen, touch and Wi-Fi retries, on a dead link. Sends now run on their own task with a 2 s limit, so a slow link no longer stalls the screen either, and a lost connection is noticed even when its event can't be queued. Contributed by Antonio Lourenco (@tozes).
- A console command that times out no longer leaves the app task writing its reply into freed memory. The request slot is shared by both tasks and freed by whichever finishes last, so a late reply is dropped instead of corrupting the stack. The slot is host-tested.
- The device refuses an over-the-air image built for another board, by reading the `HGBOARD=` tag as the image streams in, so a wrong image can no longer reach Wi-Fi and Hermes and pass the rollback check. The plugin's own check stays as the first line.
- Builds from `main` with that board check no longer refuse every over-the-air update with "the image is for , not this board". The check's search text put a nameless copy of the `HGBOARD=` tag in every image, ahead of the real one, and the device stopped at it. Images now carry the tag once, and the device, the plugin and the release packager skip a nameless tag in images built before this fix. Contributed by Antonio Lourenco (@tozes).
- A setting that cannot be saved is reported: `set` answers `@error could not save <key>`, a device key that cannot be saved is logged as an error, and a key longer than NVS allows is refused instead of silently cut.
- The CrowPanel 2.1 no longer drives GPIO 0, its BOOT key, high, so pressing BOOT while it runs no longer shorts a driven output to ground. The RGB panel setup left the display-enable pin at zero, which claimed GPIO 0 and made the ST7701 driver turn the screen on through that pin. The panel now has no enable pin, and the driver sends the display-on command over the 3-wire link instead. Not yet checked on a board.
- Display transfers no longer race their own DMA: the AMOLED-1.75/1.75C/1.8 and T-Display-S3 drivers now use the same band-by-band flush as the SPI panels, so a late or failed transfer pauses or stops drawing instead of refilling a buffer the DMA is still reading. The CrowPanel RGB path reports a failed flush or backlight change once instead of rebooting, and a display that fails to start leaves the gadget running without a screen (USB console and Wi-Fi still work) instead of rebooting in a loop. A touch task that cannot start is reported as a failed input.

### Linux

- The Raspberry Pi installer installs the release's pinned Python dependencies from a hash-checked lock file shipped in the package, wheels only, so a Pi runs exactly what CI tested instead of whatever PyPI serves that day. The release workflow runs the container install test before publishing.
- The Raspberry Pi installer checks that a new release answers on its control socket before calling the update done, and goes back to the previous release when it does not, matching the firmware's rollback. `sudo hermes-gadget-device rollback` swaps the current and previous releases by hand. A dependency installation that fails is removed instead of blocking the next attempt, the newest three releases are kept, and a release that keeps crashing at startup stops being restarted after five tries.

### Hermes plugin

- Switch which Hermes profile answers a gadget: on a touchscreen, tap the name under the mascot and pick a profile from the list; elsewhere, use **Hermes profile** in settings. Pair once, on the default profile: the plugin approves the device in each profile the first time it switches there, and revoking it on the default profile sends it back to default. Off unless the default profile's gadget `extra` sets `profiles`: `[work, home]` offers those and the default profile, `all` every profile a multiplexed gateway serves. Other profiles' configs cannot turn it on. Enable the gadget platform in the default profile only. A gadget with a `gateway.profile_routes` entry keeps its route and is not offered switching. Protocol: `hello.caps.profiles`, `welcome.profile` and `welcome.profiles`, `profile.select` and `profile` (additive; `proto` stays 1).
- `welcome` names a `language` for devices left on `auto`: the plugin's `language` setting, else Hermes's own (`agent.i18n.get_language`, so `HERMES_LANGUAGE` and `display.language` per profile). If it can't be read, `welcome` names none and the device stays in English. `hermes-gadget devserver --language es` does the same for the simulator. Contributed by Alberto Espinosa (@AlbertoEJ).
- Devices that report `charset: "latin1"` keep their accents: replies, notices, questions, cards and the dashboard are folded to ASCII and Latin-1 instead of to ASCII (`textfmt.fold_latin1`). Other scripts still fold to the nearest letter or drop, and emoji drop. Devices reporting `"ascii"` are unchanged. Contributed by Alberto Espinosa (@AlbertoEJ).
- A cancel that arrives when no turn is running no longer sends `/stop` to Hermes. Before, the stray `/stop` reached Hermes as a message of its own.
- A profile routed to the default profile's gadgets (`gateway.profile_routes`) has the gadget tools again. Hermes imports the plugin once per profile scope, so each copy kept its own empty adapter registry, the tools' availability check failed, and the agent reported `gadget_action` as missing. The registry is now one per process. The integration guide describes routing each gadget to its own profile. Contributed by Luiz Gustavo Saraiva (@luizgustavosaraiva).
- A dashboard on the device lists the Hermes agent's sessions, from every platform, as idle, busy or waiting for an approval, plus status tiles set on the host with `hermes gadget tile set nas up --state ok` (for homelab services and the like; `--ttl` makes a tile expire). Tap CANCEL on the idle screen, or swipe down on a touchscreen, to open it. Session state comes from Hermes's plugin hooks. The plugin sends a new `dashboard` message only when something on it changes, and while the screen is dark it keeps only the latest for when the screen lights up. `dashboard: false` turns it off. New firmware is needed to draw it. Checked in the simulator only, not on hardware. Prompted by @dcentgeo's ESP32-S3 watch build. [User guide](docs/using-gadget.md#watch-hermes-sessions-on-the-dashboard), [protocol](docs/protocol.md#dashboard).
- An approval whose time ran out while its device was offline no longer comes back on reconnect. Approval cards carry Hermes's approval timeout (`approvals.timeout`, 300 s by default) as their time limit, and the adapter drops a card once that time has passed.
- While a gadget's screen is dark, cards, images and status phrases wait. When it lights up, only the latest card or image and the latest status phrase are sent, and a card keeps only the time it has left. Questions, approvals, replies, audio and notices still go out at once. `gadget_display` says when its card is waiting, and `gadget_devices` reports `display_sleeping`. Firmware that doesn't report its screen is never held back. [Protocol: screen sleep](docs/protocol.md#screen-sleep).
- A command approval on a device shows the command exactly as it will run. The card used to pass through the reply formatter, which strips Markdown: `ls <think>; curl … | sh ;</think>` showed as `ls`, and TALK approved the whole command. A command that doesn't fit one line of the device's screen as-is (longer, multi-line, with a tab, double space or non-ASCII character) now shows "Can't show this command": CANCEL denies it and TALK does nothing, so it is approved on the host. Reported in the Hermes plugin catalog review.
- A device that loses its pairing loses its open questions, and an answer from an unpaired session is ignored. A revoked device could still answer a question queued before the revocation.
- The plugin README shows how to bind `host` to one interface and serve `wss://` with `tls_cert` and `tls_key`.
- The plugin declares the Hermes it needs (`requires_hermes: ">=0.21.6"`, the first release with the commit CI tests against), and has its own README: what it adds, and what it does on your machine (the port it opens, who can connect, approvals answered from a device, the home channel, `ffmpeg`, firmware downloads, the files it writes and the Hermes services it uses). This prepares it for the Hermes plugin catalog.
- A question from the agent (the `clarify` tool) is spoken on devices that speak replies, with its choices read out by number, as well as shown as text. It used to arrive as text only, so a voice user heard nothing while the agent waited for an answer. The next spoken or typed message answers it, as before. Contributed by Antonio Lourenco (@tozes).
- `battery_log: true` in the gadget platform's `extra` keeps each paired device's battery readings (voltage, percent, charging, USB power) in a CSV under the plugin's data directory, a row every 30 seconds, to calibrate a board's battery percentage from a full discharge. Off by default. Contributed by Antonio Lourenco (@tozes).
- Spoken replies stay paced after the text-to-speech producer pauses. A sign error in the hub's stall handling let the rest of a reply go out in one burst after the first pause, which could overflow a device's speaker buffer. A fake-clock test now holds every frame within the playback lead, before and after a stall.
- Enrollment by unapproved devices is bounded: at most 16 may wait to be paired, 4 per network address, and an unapproved record expires an hour after the device's last contact. `hermes gadget pair --yes` approves blindly only when one device is waiting; `hermes gadget pair <device>` picks one. `hermes gadget devices` marks devices still waiting to pair.
- `hermes gadget forget` takes effect on a running gateway. The device store re-reads `devices.json` before every operation and writes through a per-process temporary file, so the gateway no longer keeps a stale copy of a forgotten key or writes it back when the device reconnects.
- The plugin checks, before the gateway creates the adapter, that this Hermes still has every module and private adapter hook it relies on, and fails with a message naming what is missing and the Hermes commit it was tested against. The tested commit lives in `plugin/compat.py`, and a test keeps it equal to the CI pin.
- A too-short utterance no longer leaves the device on "Sending..." until its three-minute timeout. The server now sends its "Didn't catch that" notice and a cancelled `turn.end`, so the device returns to ready at once. On touch devices the notice names the screen instead of the button.

It shows how to check the scan with `hermes plugins validate` before installing. A release now requires successful CI and Hermes runs on the tagged commit and a `CHANGELOG.md` section for the version, which opens the release notes. The security policy covers `linux/`.
- The Linux guide names the real approval command, `hermes gadget pair`. A test now checks that every `hermes gadget` and `hermes-gadget` command in the guides exists in the CLIs.
- CI installs libopus on the Ubuntu Python jobs and sets `HG_REQUIRE_LIBOPUS=1`, so the Opus encode/decode round trip and bitrate tests run there and fail, not skip, if the library can't load.
