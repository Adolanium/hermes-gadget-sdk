# TailTiny (vendored)

`tailtiny/` and `wireguard_lwip/` are [TailTiny](https://github.com/Asimmimx/tailtiny) 3.0.2 at commit `450ad519810f0a7560306e1389c65acf2c48828c`: `components/tailtiny/` there, with its `LICENSE` and `x25519-license.txt` from the repository root, and the `wireguard_lwip` it nests in `components/` moved up beside it so ESP-IDF finds both. This repository stores the files with LF line endings; upstream's are CRLF. Licenses: [TailTiny-MIT](../../../LICENSES/TailTiny-MIT.txt), [wireguard-lwip-BSD-3-Clause](../../../LICENSES/wireguard-lwip-BSD-3-Clause.txt), [STROBE-x25519-MIT](../../../LICENSES/STROBE-x25519-MIT.txt).

Each change below has its own patch in `tailtiny-patches/`, applied in order with `patch -p1 -d firmware/esp32/components`. To compare with upstream, `diff -r --strip-trailing-cr` a fresh copy, laid out as above, against these directories.

To update: copy the new upstream release the same way, then reapply the patches in order and resolve what no longer applies.

## Changes

1. **Build** (`01-build.patch`). ESP-IDF 6 and this firmware:
   - Both `CMakeLists.txt` compile their sources only with `CONFIG_HG_TAILNET` (`main/Kconfig.projbuild`); their requirements stay unconditional, because ESP-IDF resolves requirements before the sdkconfig exists. TailTiny's Kconfig menu depends on `HG_TAILNET`.
   - `idf_component.yml` drops the nested `wireguard_lwip` path (it now sits beside TailTiny) and adds `espressif/cjson`: ESP-IDF 6 no longer ships cJSON as `json`. `REQUIRES` names `espressif__cjson`, and `esp_driver_uart` because ESP-IDF 6 dropped UART from `driver`.
   - `src/ml_cellular.c` (the 4G modem driver) isn't compiled: cellular stays off, and the file includes `driver/uart.h` outside its `#ifdef`.
   - `-Wno-unterminated-string-initialization` for both components: GCC 15 flags byte arrays initialised from strings of exactly their length (HSalsa20's sigma, WireGuard's protocol labels), which is deliberate.
2. **Mbed TLS 4: PSA randomness for the relay's TLS** (`02-mbedtls4-randomness.patch`). ESP-IDF 6 ships Mbed TLS 4, where TLS draws randomness from PSA and the entropy and CTR-DRBG modules are private. In `src/ml_derp.c` and `include/tailtiny_internal.h`, the DERP connection's entropy and CTR-DRBG contexts, their seeding and `mbedtls_ssl_conf_rng()` stay only for Mbed TLS 3.
3. **The Noise channel's ChaCha20-Poly1305 from wireguard-lwip** (`03-noise-chachapoly.patch`). Mbed TLS 4 made its ChaCha20-Poly1305 API private, so `src/ml_noise.c` uses the reference implementation that wireguard-lwip bundles, through two small functions in the new `src/ml_noise_aead.h`. Tailscale's nonce is 4 zero bytes, then the counter big-endian; wireguard-lwip writes its 64-bit nonce little-endian into the same 8 bytes, so the counter is passed byte-swapped. `firmware/tests/test_tailtiny_aead.cpp` checks wireguard-lwip against RFC 8439's appendix A.5 vector, the wrapper against the same vector with the counter placed big-endian, the wrapper against Python's `cryptography` for four other counters, and that a changed byte, counter or truncated message is refused.
4. **The relay's certificate is verified** (`04-relay-certificate.patch`). Upstream connected to the DERP relay with `MBEDTLS_SSL_VERIFY_NONE`. `src/ml_derp.c` now calls `ml_derp_tls_verify()` from the new `src/ml_derp_tls.h`, which requires the certificate to chain to the firmware's CA bundle (`esp_crt_bundle_attach`) and to match the relay's host name, which `ml_derp.c` already sets. WireGuard already encrypts what the relay carries; this stops a network in the middle from posing as the relay. `firmware/tests/test_tailtiny_tls.cpp` runs the same setup against a local TLS server on Mbed TLS 4.1.0: a certificate from a trusted CA for the right host is accepted, and a self-signed certificate, a trusted one for another host, and a failed CA attach are refused. It's built with `-DHG_TLS_TESTS=ON` ([development](../../../docs/development.md#test-suites)).
5. **Why registration failed is kept** (`05-registration-error.patch`). `src/ml_coord.c` and `include/tailtiny_internal.h`: a new `last_error` field holds why registration last failed (the auth key was rejected, the device waits for approval, or the control server's own reason), and is cleared on connect, so the device screen can say what's wrong. Upstream only logged it.
